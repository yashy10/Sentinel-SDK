# Bastion Guard Enforcement Logic

## Overview

The enforcement system implements four enforcement actions that match the formal specification. Each enforcement action has a specific end-to-end flow.

## Enforcement Actions

### 1. USER_INSPECTION (USER_INPUT)

**Formal Effect**: If user denies, the trajectory is modified to end the agent's execution instead of executing the risky action.

**End-to-End Flow**:
1. Rule triggers and all predicates are true
2. Enforcement logic stops the planned action
3. System prompts user with summary/context of planned action
4. User approves or denies execution
5. **Approve** → Agent continues, action executes
6. **Deny** → Action aborted, agent's execution terminated

**Implementation**:
- Uses `ctx.ask()` with `permission: "bastion"`
- If user approves: Continues with original args, logs as "EXECUTED"
- If user denies: Throws error terminating agent execution, logs as "BLOCKED"

**Use Case**: Human oversight for risky operations

---

### 2. LLM_SELF_EXAMINE (LLM_EXAMINE)

**Formal Effect**: Transform the current planned action into a safer alternative generated by the LLM. The corrected action replaces the original in the agent's execution trajectory.

**End-to-End Flow**:
1. Rule conditions detect an unsafe action
2. System invokes LLM to self-examine the situation
3. LLM generates a corrective action or alternative plan that complies with safety rules
4. The corrected action replaces the original in the agent's execution trajectory
5. If same tool: Corrected args substituted, execution continues
6. If different tool: Error thrown with corrected action info, agent retries

**Implementation**:
- Calls `Bastion.llmExamine()` which prompts LLM for corrected action
- Returns `CorrectedAction` with `toolName`, `toolArgs`, `explanation`, and `learnedConstraint`
- If corrected tool matches original: Substitutes `bastionArgs` and continues
- If corrected tool differs: Throws error with corrected action details
- Learned constraint is saved to memory for future prevention

**Use Case**: Automatically repairing or adapting actions when unsafe behavior is detected without requiring human input

---

### 3. INVOKE_ACTION

**Formal Effect**: The specified action is executed immediately, updating the agent's trajectory accordingly.

**End-to-End Flow**:
1. Rule trigger and predicate conditions are satisfied
2. Instead of continuing original action, enforcer substitutes it with predefined safe action
3. Agent executes that action with given parameters
4. If sanitized action is still unsafe: Falls back to KILL

**Implementation**:
- Calls `Bastion.sanitize()` to generate safe substitution
- Re-validates sanitized action with `Bastion.check()`
- If safe: Substitutes `bastionArgs` and continues execution
- If unsafe: Falls back to KILL enforcement (terminates)

**Use Case**: Automatically applying corrective operations (e.g., adjusting speed, turning on hazard lights)

---

### 4. STOP (KILL)

**Formal Effect**: The agent's execution trajectory is terminated by replacing the next action with a finish action.

**End-to-End Flow**:
1. Rule is triggered and predicates return true
2. Enforcement logic chooses STOP
3. Agent's planned action is canceled
4. Agent's task terminates immediately

**Implementation**:
- Throws error with `Bastion.killMessage(verdict)`
- Logs as "BLOCKED" in audit trail
- Error propagates up, terminating agent execution

**Use Case**: Absolute safety cut-off for high-risk violations that should not be allowed under any circumstances

---

## Enforcement Selection

When an action is blocked, the user is presented with all 4 enforcement options:

1. **STOP (KILL)** ⭐ (if recommended)
2. **USER_INSPECTION (USER_INPUT)** ⭐ (if recommended)
3. **LLM_SELF_EXAMINE (LLM_EXAMINE)** ⭐ (if recommended)
4. **INVOKE_ACTION** ⭐ (if recommended)

The recommended enforcement is based on the rule's default enforcement action, but the user can override it.

## Learning System

Every blocked action (regardless of enforcement type) creates a learned constraint:
- Saved to `.opencode/bastion_memory.json`
- Fed back into Bastion Guard for future matching
- Injected into LLM system prompt for prevention

When a learned constraint matches:
- Shows "🧠 LEARNED CONSTRAINT MATCHED" message
- Explains that action was previously blocked
- Still presents enforcement selection options
